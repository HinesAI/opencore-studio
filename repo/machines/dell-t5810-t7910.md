# Dell Precision T5810 / T7810 / T7910 (X99 / C612)

Studio profiles: `intel_haswell_e` (E5 v3) and `intel_broadwell_e` (E5 v4).

Chipset is C612 (X99 class). Dual-socket T7910 is the same ACPI family as T5810 with more CPU devices.

## Hardware facts

- No consumer iGPU — AMD dGPU with UEFI GOP required
- Onboard Intel LAN → IntelMausi
- BIOS: AHCI, Secure Boot off, VT-d off (or DisableIoMapper), latest A-series firmware (T5810 notes A32–A34; T7910 use what Dell still signs)
- Front USB is proprietary. Installer on a **rear** port
- 64-thread cap reports in macOS on busy dual-socket boards (InsanelyMac T7910 Sonoma)

## Dortania baseline (must)

From Haswell-E / Broadwell-E pages:

- SSDT-PLUG, SSDT-EC-USBX, SSDT-RTC0-RANGE (file: RTC0-RANGE-HEDT), SSDT-UNC
- CPUID spoof matching **v3 vs v4**
- AppleXcpmCfgLock (if CFG-Lock), AppleXcpmExtraMsrs, DisableIoMapper, PanicNoKextDump, PowerTimeoutKernelPanic, DisableLinkeditJettison
- IgnoreInvalidFlexRatio
- LegacyOverwrite YES, WriteFlash NO
- SetupVirtualMap YES, DevirtualiseMmio **NO**
- iMacPro1,1 or MacPro7,1
- Boot-args: `-v keepsyms=1 debug=0x100 alcid=?` + `agdpmod=pikera` if Navi

## The Dell TSC bug (Monterey+)

Firmware leaves IA32_TSC_ADJUST inconsistent across cores. Kernel panic text: **Non-monotonic time**. This is **after** EXITBS. Verbose looks like a kernel panic, not a boot.efi stop.

History:

| Era | What people used | Problem |
| --- | --- | --- |
| Monterey first wave | `cpus=1` | Boots one thread |
| T5810 Ventura threads | denskop **ResetTSCAdjust.efi** as a UEFI **Driver** | Works if the file is present |
| BillDH2k T5810 EFI | that EFI in Drivers; later dropped CpuTscSync.kext because sleep was disabled | Sequoia notes still mention the EFI |
| OpenCore 1.0.6/1.0.7 | **file not in the RELEASE zip** | Enabling it **halts OpenCore** |
| Studio now | **CpuTscSync.kext** (acidanthera) + `TscSyncTimeout=500000` | Lilu plugin; Monterey+ resets TSC_ADJUST; also helps S3 if you enable sleep later |

Do not list ResetTSCAdjust.efi unless we vendor the binary into Drivers first.

CpuTscSync GitHub: https://github.com/acidanthera/CpuTscSync/releases (`CpuTscSync-*-RELEASE.zip`). Load after Lilu.

## Community EFI extras (optional, not all in Studio yet)

From BillDH2k and Klubuntu T5810 repos + T7910 InsanelyMac:

- AppleALC **layout 17** on T5810 ALC280 — verify codec on T7910
- USBMap built for **that** chassis (MacPro7,1 personality)
- X99 USB3 injector (they later cleaned it)
- SSDT-SBUS-MCHC
- NVMeFix if NVMe is on a PCIe adapter (common in these towers)
- Toggle “Memory Map I/O Above 4G” and/or Legacy Option ROMs if `OCB: StartImage failed` after a CPU swap
- Sleep/wake often left **disabled** on Dell C612; don’t chase S3 until TSC is proven

T7910 InsanelyMac also experimented with SSDT-PCI1 for extra slots and simplified USBX/SBUS SSDTs (etorix). Only add if devices are missing in IOReg.

## Studio EFI checklist

- [ ] Profile matches CPU (v3 vs v4)
- [ ] CPUID DATA/MASK non-empty
- [ ] Four SSDTs on disk **and** in ACPI Add
- [ ] CpuTscSync.kext on disk **and** Kernel Add, after Lilu
- [ ] TscSyncTimeout ≠ 0
- [ ] UEFI Drivers = only files that exist (OpenRuntime, HFS, ResetNvramEntry)
- [ ] No ResetTSCAdjust.efi row
- [ ] HideAuxiliary false so Reset NVRAM is in the text picker
- [ ] Navi: agdpmod=pikera
- [ ] Copy **this** EFI to the USB; old folder still has the halt

## BIOS reminder (Dell)

SATA AHCI. Secure Boot disabled. VT for Direct I/O disabled. Above 4G: try ON; if OC fails to StartImage, toggle it once. Serial off. CSM off.

A working EFI on these towers should reach the picker and the installer (or an installed volume) without a non-monotonic time panic and without OpenCore stopping on a missing UEFI driver.
